# Stufe 8b: Gesamtprüfung

Die Anforderungen sind einzeln geprüft — hier wird geprüft, ob sie **zusammen** funktionieren:

-   Alle Tests, der Prüflauf, die automatischen Prüfungen aus Stufe 6 und der saubere Lauf auf `release-candidate`.
-   **Zurückgestelltes aufräumen** (`_requirements/deferred/`, Regeln in der `README.md` dort; bei der Abkürzung gilt deren Abschnitt dazu): Übernommenes oder Erledigtes löschen; was jetzt jemand will, als Issue festhalten und erst danach löschen (Einzelheiten in der `README.md` dort); dem Nutzer kurz nennen, was bleibt. Die Änderungen gehen mit dem Commit des Release-Dokuments.
-   Kurzer Klicktest über alle enthaltenen Anforderungen (Rolle Klicktester, nur die Hauptwege) — dem Klicktester Version und Liste der Anforderungen nennen. Die Befunde stuft der Agent ein (`_agent-process/anweisungen/rollen/README.md`).
-   Ergebnis unter `# Gesamtprüfung` ins Release-Dokument; damit ist es **fertig** — committen, pushen. Läuft 8b nach Befunden erneut, ersetzt der Agent diesen Abschnitt (Zuordnungen `<datei>` → `#<Nummer>` aus früheren Läufen übernehmen); eingefroren ist das Release-Dokument erst ab dem Zusammenführen nach `main`. Das Ergebnis der CI steht im Pull Request, nicht im Dokument.
-   Dann eröffnet der Agent den **Pull Request von `release-candidate` nach `main`** (Titel z. B. `chore(release): v<version>`; in der Beschreibung `Closes #<Nummer>` für jedes Dokument, das seit dem letzten Tag nach `_requirements/done/` kam — `git diff --name-only --no-renames --diff-filter=A <letzter Tag>..HEAD -- _requirements/done/` (letzter Tag: `git describe --tags --abbrev=0`), ohne Tag alle; Nummer aus der Zeile `Issue`, fehlt sie: weglassen; so ist auch ein Fix aus 8b dabei) — beim erneuten 8b gibt es ihn schon, dann die Beschreibung ergänzen; die CI läuft dort. **Ohne grüne CI kein Zusammenführen und kein Tag.** Dem Nutzer sagt er: Pull Request `#<Nummer>`, CI grün, bereit zum Zusammenführen.
-   Blockierende Befunde → betroffene Anforderung über einen Fix-Branch korrigieren — abgezweigt vom aktuellen `release-candidate`, Pull Request dorthin; zuerst als Issue festhalten (Stufe 1), dann Klärung wie in Stufe 2 (`_agent-process/skills/ap-requirement-refine/klaeren.md`, „Beginn" mit den Punkten darunter) (das abgenommene Dokument bleibt eingefroren); dem Nutzer sagen: Pull Request `#<Nummer>` vorerst nicht zusammenführen; danach 8b erneut, vorher `release-candidate` auf aktuellen Stand bringen. Empfohlene Befunde und Hinweise: als Eintrag `release-<version>-<n>.md` in `_requirements/deferred/` (vor dem Commit des Release-Dokuments), als Issue festhalten (Stufe 1) oder mit Grund verwerfen; das Release geht weiter.
